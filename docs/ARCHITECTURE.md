## 一、设计目标与约束

### 选题书要求 → 设计响应

| 要求 | 设计响应 |
| --- | --- |
| 用 ImageNet 预训练 ResNet18 | 取 avgpool 512 维特征，不微调、不训练 |
| 物体录入 + 特征保存 | 多视角采样 → SQLite + NumPy 特征库 |
| 识别返回名称 + 相似度 | 余弦检索 Top-K，附带相似度百分比 |
| 相似度低时显示未知物体 | 阈值 + 分数差距双重判定（见第五节） |
| 语音说出物体名称 + 语音播报 | Paraformer ASR + Edge TTS（断网降级 mock） |
| 简单界面 | Flask 浏览器页面（视频流 + 深度图 + 物体库） |
| ≥5 物体 ×≥5 图，≥3 未录入物体 | 场景测试图已入库于 `data/test_scenes/` |

### 部署环境约束（决定全部技术选型）

目标机器：**Windows + Intel iGPU / CPU，无 NVIDIA 显卡，尽量离线**。

| 约束 | 影响 |
| --- | --- |
| 无 CUDA | 不用 TensorRT / PyTorch GPU 路径；ONNX Runtime CPU |
| 运行时不装 PyTorch | torch 仅一次性导出 ResNet18，运行只需 onnxruntime |
| 需完全离线 | 视觉/ASR/NLU 全本地；NLU 用规则不用 LLM |
| 演示链路要稳 | 砍掉可选组件，减少模型下载与失败点；单入口、单配置 |

       │             │

### 分层原则

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| `web/` | HTTP 服务、MJPEG 编码、页面 | 不做业务判断、不做识别 |
| `core/` | 线程编排、生命周期、组件装配 | 不含视觉/语音算法、不画 GUI |
| `vision/` `voice/` | 算法实现 | 不感知 Flask，不直接控制线程 |
| `nlu/` | 文本 → 意图 | 不访问摄像头或特征库 |

`vision/` 和 `voice/` 完全可独立测试。`tools/` 的脚本直接 import 这些模块做
批量评测，无需启动网页、无需摄像头。

## 三、线程模型

`AssistantApp.start()` 最多启动 4 个 daemon 线程 + Web 自带 1 个渲染线程：

| 线程 | 目标函数 | 频率 | 说明 |
| --- | --- | --- | --- |
| Flask 主线程 | `app.run` | 请求驱动 | 处理 REST，不跑推理 |
| web-frames | `web/server._frame_loop` | ~30 FPS | 只取最新帧、cv2 画框、JPEG 编码 |
| camera | `Camera._loop` | 尽可能快 | 覆盖式写 `latest` 帧缓冲 |
| depth | `_depth_loop` | ~2 Hz | 低分辨率深度图（320px）供热力图 |
| voice | `_voice_loop` | VAD 端点触发 | mic → VAD → ASR → 意图队列 |
| intent | `_intent_loop` | 队列驱动 | 识别/录入/查找，真正跑 ResNet18 |

### 核心约束：渲染永不阻塞

网页帧循环只做「取最新帧 → 降采样 → 画框 → 编码 JPEG」，任何耗时推理都不在
渲染路径上。深度热力图约 2 Hz 才变，JPEG 缓存复用，不逐帧重编码。

### 帧缓冲区与背压

`Camera.latest()` 语义是「拿最新的那一帧」，不是「排队取帧」：覆盖式缓冲保证
网页永远显示当前画面，代价是可能丢帧——交互式 UI 里延迟比丢帧更影响体验。

### 资源开关与降级

`set_recognition_enabled()` 是总开关：暂停时连摄像头、麦克风、深度推理、
MJPEG 编码一起释放（这三个是主要 CPU 消耗），摄像头预览保持以便随时恢复。
摄像头、麦克风也可各自独立开关。

| 失效组件 | 降级行为 |
| --- | --- |
| 深度模型缺失 | 回退画面中心 45% ROI，功能可用 |
| ResNet18 缺失 | 明确提示运行 `prepare_models.py --resnet18`（实质影响功能） |
| 麦克风缺失 | 自动切到网页文字输入 |
| Edge TTS 断网 | 自动降级为 mock 提示音，识别不受影响 |
| 画面质量差 / 未定位到物体 | 明确提示重举，不静默误匹配 |

## 四、视觉链路

### 职责划分：深度定「剪哪一块」，ResNet18 定「这是什么」

这是本项目最关键的设计取舍：

```
Depth Anything V2 ──→ 依据「什么离镜头最近」生成候选区域（零类别、零提示）
ResNet18          ──→ 判断裁剪区域是什么东西（特征检索，用户教什么认什么）
```

**为什么用深度而不是检测器**：YOLO 是 COCO 80 类的闭集检测器，用户自定义的
「我的蓝色水杯」不在词表里，会退化成固定类别名。识别环节是零样本的，若定位
环节依赖类别先验，叙事就站不住。单目深度用几何信息（最近 = 用户手持/关注的
物体）回答定位，天然零类别。选型论证见 [技术报告](zero_shot_depth_localization.md)。

### 候选区域流水线（`vision/depth.py`）

```
摄像头帧 (1080p BGR)
  → Depth Anything V2 Small (ONNX Runtime CPU, 518×518)
  → 相对深度归一化 [0,1]（0=近，1=远）
  → 近景阈值分割：取最近 20% 像素（near_percentile=80）
  → 形态学闭 + 开（合并碎片、去噪）
  → 连通域分析 → 打分：0.35×面积 + 0.30×中心邻近 + 0.35×深度接近
  → 取 top-4 区域交给特征 matcher 选真正目标
```

取 top-4 而非只取第一名：杂乱场景里深度有歧义，让特征检索从多个候选中挑
真正的目标，比盲信单次深度猜测更稳。

### 候选过滤（避免把人/背景当物体）

| 过滤 | 手段 |
| --- | --- |
| 太远的区域 | 与最近候选的深度差 > `depth_gate` 则丢弃（手持物体比人脸/背景近） |
| 人脸/人像 | 近景肤色比例检测 + 可选 Haar 级联；用原始区域判断（掩码会把肤色涂掉导致漏检） |
| 过大框 | 占画面 > 50% 的通常是人/场景，不是 discrete 物体 |
| 低质量裁剪 | 尺寸 < 64px、全黑/过曝、纯色（拍空）一律拒绝 |

深度跑了但所有候选都被拒 → 直接答「没看到明显物体」，**不**回退中心 ROI
（否则会把画面中央的人脸误匹配进物体库）。只有深度模型整体不可用时才走中心 ROI。

### 预处理与特征

| 步骤 | 参数 |
| --- | --- |
| 缩放 | 224×224，`INTER_AREA` |
| BGR → RGB + `/255` | OpenCV 是 BGR，ImageNet 按 RGB 训练 |
| 归一化 | 减均值除标准差（ImageNet 统计量） |
| NCHW | `transpose(2,0,1)[None]` |
| 输出取 avgpool | 512 维，**在 fc 之前** |
| L2 归一化 | 余弦相似度 = 点积 |

取 fc 之前是因为 fc 输出 1000 类 ImageNet 分布，做检索冗余且类别相关；avgpool
的 512 维是通用语义特征，更适合实例检索。

### 抗旋转

ResNet18 不是旋转不变的。`_match_crop()` 对同一裁剪尝试 4 个 90° 视角，加掩码
去斜后的 4 个视角，取「分数达标且与次名分差足够」的那个视角；不达标则返回最优
候选由上层判未知。这样不必为旋转样本重新录入。

## 五、特征库设计

### 存储分层

```
data/visual_memory.db          SQLite：物体元数据 + 样本索引（可查询、可删）
data/resnet18_embeddings.npz   NumPy：压缩特征矩阵，启动时秒级加载
data/samples/<name>/*.png     样本图（人工核对用）
data/samples/<name>/*.npy     对应特征（重建索引的数据源）
```

**为什么分离**：余弦检索要遍历全库，SQLite 逐行读太慢；把特征抽成连续矩阵，
一次 `np.load` 全量载入内存，检索变成一次矩阵乘 `scores = matrix @ query`。
SQLite 只管元数据（按名查询、列出物体、级联删除），量小且是关系操作。

几十个物体、几百到几千个 512 维向量，矩阵乘是微秒级，用不上 FAISS。

### 共同成分去除（centering）

实测 ResNet18 的 avgpool 特征约 **86% 的分量是所有照片共有的**（光照、纹理、
背景统计），导致两个不相关物体也有 ~0.6 余弦。启用 `center_features` 时，
检索前先减去特征库均值再做余弦：跨物体相似度显著下降，同物体仍保持高分。

阈值和判据随之切换到 `match_threshold_centered`（0.5）与
`margin_threshold_centered`（0.15）；未启用或库内物体 < 2 时回退普通特征与阈值。

**双重判定**（识别返回三态）：

- `best_score ≥ 阈值` 且 `top1 − top2(不同物体) ≥ margin` → 名称 + 相似度
- 分数达标但分差不足 → 「不太确定，看起来像 X，但 Y 也很相似」
- 分数不达标 → 「未知物体」

分差判据是因为 ResNet18 对形状近似物体（如碗/马克杯）可能给出相近的高分，
仅看绝对分数会误认。

### 维度自愈

换模型后残留旧维度特征会静默出错，代码三重防御：载入校验维度不符则重建索引；
重建时跳过维度不符的 `.npy`；清理没有任何特征的残留物体。

## 六、语音链路

### 进程与线程

语音输入（VAD + ASR）在主进程独立线程，不阻塞渲染。TTS 也在独立 worker 线程，
`say_async()` 入队即返回，识别链路不等它。

### 语音输入

| 环节 | 实现 |
| --- | --- |
| VAD | Silero VAD ONNX；500ms 预卷缓冲保留语句开头（避免「这是什么」被切成「这是」） |
| 端点决策 | 停顿 600ms 且解析出已知意图就立即触发，典型延迟从 ~2.5s 降到 ~0.6s |
| ASR | sherpa-onnx Paraformer INT8；兼容端到端单模型与 encoder/decoder 双模型两种布局 |
| 半双工 | 播报后按文本长度短暂静音麦克风，避免 TTS 被自己识别回去 |

### 语音输出（edge + mock）

| `tts.mode` | 联网 | 说明 |
| --- | --- | --- |
| `edge`（默认） | 是 | 微软 Edge TTS，延迟低、中文音色自然 |
| `mock` | 否 | 按回复长度生成提示音，无网络也能跑通全链路 |

任何 edge 失败（无网、SDK 缺失、合成静音）都会自动回退 mock，不抛错给主流程。

### 必须绕过系统代理

本机设了 `http_proxy` 时，`urllib` 可能把本地回环也塞进隧道导致 502。因此
所有本地 HTTP 客户端都显式用 `ProxyHandler({})` 绕过代理——排查「页面打不开 /
本地连接被拒」时优先确认这一点。

## 七、意图解析

`nlu/intent.py` 用**有序正则**匹配 6 类意图（识别 / 录入 / 查找 / 删除 / 列表 / 帮助），
返回 UNKNOWN 兜底。不用 LLM，因为：离线要求 + 中文指令句式高度固定 + 零延迟
零成本 + 可解释（每个 pattern 对应什么说法一目了然）。

**顺序敏感**：更具体的模式必须先试。

```
LIST 必须先于 REMEMBER —— 否则「你记住了什么」会匹配「记住…」
REMEMBER 必须先于 SEARCH ——「记住，这个叫X」含「叫」
```

解析前先做文本规整：去标点、去所有空白（Paraformer 常在汉字间插空格），并对
常见误听做纠错（把「技术/即是」纠回「记住」，合并重复的「这个这个」等），
迭代到不动点。物体名字符集支持中英文数字与 `·` `-`，长度上限 32 防回溯。

## 八、配置体系

单一配置源 `config/demo.yaml`，`core/config.py` 负责加载并把相对路径解析为
绝对路径（相对项目根），从任意工作目录启动都不会找错文件。

覆盖优先级：**CLI 参数 > 环境变量 `ASSISTANT_CONFIG` > YAML 默认值**。

关键阈值都不写死在代码里，便于现场按效果微调。注意 `match_threshold_centered`
是针对当前演示数据集的设置，**不是通用最优阈值**，换物体集合后需重新观察边界。

## 九、关键设计决策（为什么不）

| 决策 | 理由 |
| --- | --- |
| 深度定位而非闭集检测器 | 识别零样本，定位也应零类别；几何最近比类别词表更贴合「用户举起的东西」 |
| 特征取 avgpool 而非 fc 输出 | fc 是 1000 类分类头、类别相关；avgpool 是通用语义特征 |
| ResNet18 不微调 | 选题书要求；少量样本微调必过拟合 |
| 减均值 + 分数差双重判定 | raw 特征 86% 是共有分量；近似物体绝对分接近，需分差兜底 |
| NumPy 而非 FAISS | 几十物体，矩阵乘微秒级，引入依赖不划算 |
| 覆盖式帧缓冲不用队列 | UI 要「当前画面」而非「不丢帧」 |
| 深度跑了就拒识而不回退中心 ROI | 避免把画面中央的人脸误匹配进库 |
| 规则 NLU 不用 LLM | 离线 + 句式固定 + 可解释 |
| 只留浏览器界面 | 减少入口与依赖，演示路径唯一、稳定 |
| Edge TTS 自动降级 mock | 有网时音色自然，断网也不中断演示 |
| 默认关闭画面落盘 | 避免把课堂参与者肖像写入磁盘 |

## 十、已知局限

- **类别粒度受限**：ResNet18 是分类 backbone，形状近似但类别不同的物体
  （如碗 / 马克杯）区分力有限；`margin` 判据能识别「不确定」，但不能保证区分。
- **依赖光照与视角**：录入与识别的光照角度差异过大会拉低余弦相似度。
- **深度定位非万能**：纯色/透明/反光物体、杂乱背景、手遮挡都可能让候选包含
  背景或截断物体；阈值与校正只能改善部分场景。
- **帧率不等于推理速度**：网页 30FPS 是渲染帧率；CPU 上深度推理数百毫秒，
  按需触发，与界面刷新独立。
- **单机单进程**：SQLite + 内存矩阵适合几十到几百物体的课程规模。
- **全离线真人播报需另配**：本分支默认 Edge TTS 需联网；完全离线且要真人声音
  需额外部署 GPT-SoVITS（见 `master` 分支）。
